## ADDED Requirements

### Requirement: Bridge path enqueues kernel to GPUContext

When `cudaLaunchKernel` is called and `g_cpptlm_bridge != nullptr`, the system SHALL additionally enqueue the kernel launch to `GPUContext::task_queue` for PTX instruction execution (not just the CppTLM bridge submit).

- SHALL create a `KernelLaunchRequest` with the same parameters as the non-bridge path
- SHALL use the same `kernel_id` as the bridge path for consistency
- SHALL deep-copy kernel args once and move them into the `KernelLaunchRequest` (no double copy)
- SHALL set `on_complete` callback to call `g_ptx_emu_driver->mark_complete(kernel_id)`

#### Scenario: bridge path creates dual submission

- **WHEN** `cudaLaunchKernel` executes with `g_cpptlm_bridge != nullptr`
- **THEN** SHALL call `g_cpptlm_bridge->submit_kernel(...)` (existing behavior preserved)
- **THEN** SHALL additionally call `g_gpu_context->submit_kernel_request(...)` with same `gridDim`, `blockDim`, `sharedMem`, and args

#### Scenario: kernel_id is consistent across both paths

- **WHEN** bridge path enqueues to `GPUContext::task_queue`
- **THEN** the `KernelLaunchRequest` SHALL use the same `kernel_id` as generated by `generate_kernel_id()` for the bridge path

#### Scenario: args deep copy is single-shot

- **WHEN** kernel args are deep-copied for the bridge path
- **THEN** the same deep-copied args SHALL be used for the `GPUContext::submit_kernel_request()` call
- **THEN** args SHALL NOT be deep-copied twice

#### Scenario: on_complete callback marks completion

- **WHEN** `GPUContext` finishes executing the enqueued kernel
- **THEN** SHALL invoke `on_complete` callback
- **THEN** SHALL call `g_ptx_emu_driver->mark_complete(kernel_id)`
- **THEN** CppTLM `is_kernel_complete(kernel_id)` SHALL return `true` on subsequent checks

#### Scenario: on_complete handles null driver gracefully

- **WHEN** `g_ptx_emu_driver` is nullptr at the time of `on_complete` invocation
- **THEN** SHALL skip the `mark_complete` call (no crash)
