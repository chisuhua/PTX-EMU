## Requirements

### Requirement: Documentation index covers all subdirectories
`docs/README.md` SHALL list every direct subdirectory of `docs/` (excluding `docs/README.md` itself) in its index table, with each row containing: directory name (linked), 1-2 sentence purpose description, and primary content type (ADR/plan/audit/report/skill/reference).

#### Scenario: Index includes all 17 current subdirectories
- **WHEN** a developer opens `docs/README.md`
- **THEN** the index table contains entries for: adr/, appendix/, architecture/, archive/, audits/, dev-process/, developer-guide/, plans/, ptx/, reports/, research/, roadmap/, skills/, superpowers/, technical_design/, testing/ (16 entries minimum; updates as subdirs are added)

#### Scenario: New subdirectory triggers README update
- **WHEN** a new directory is created under `docs/`
- **THEN** the change adding that directory MUST also update `docs/README.md` index to include the new entry in the same commit

#### Scenario: Subdirectory removal triggers README update
- **WHEN** a directory under `docs/` is removed
- **THEN** the change removing that directory MUST also update `docs/README.md` index to remove the entry in the same commit

### Requirement: Documentation statistics are auto-generated
Statistical claims in `docs/README.md` (such as "X test cases", "Y LOC", "Z commits") MUST be generated by scripts and MUST NOT be hand-edited. If a statistic is removed, the script that generated it SHALL also be removed.

#### Scenario: Test case count is generated
- **WHEN** a developer runs `scripts/check-docs-index.sh` (or equivalent)
- **THEN** the script reports the current test case count via `grep -r "TEST_CASE" tests/ | wc -l` rather than relying on a hand-written number in the README

#### Scenario: Stale hand-edited statistics are rejected
- **WHEN** `docs/README.md` contains a hardcoded number (e.g., "38 test cases") in a statistical context
- **THEN** the check script flags it as a violation requiring replacement with a generated reference

### Requirement: Orphan OpenSpec archive changes have a README pointer
Every `openspec/changes/archive/<date>-<name>/` directory that lacks `design.md` MUST contain a `README.md` with: (1) one-sentence purpose, (2) implementation commit hash, (3) related ADR number if applicable.

#### Scenario: New orphan change requires README
- **WHEN** an OpenSpec change is archived without `design.md` (e.g., due to historical partial-record situation)
- **THEN** the archive commit MUST include a `README.md` in the same change directory before the change can be considered fully archived

#### Scenario: README references verifiable commit hash
- **WHEN** an archive change's README contains a commit hash reference
- **THEN** `git log --all --oneline -- openspec/changes/archive/<date>-<name>/` MUST include that commit (verifiable via `git show <hash> --stat`)

### Requirement: Stale or corrected documents display a banner
Documents with known staleness (e.g., superseded by newer audit) or factual errors (e.g., corrected by errata) MUST display a `> **⚠️ ...**` blockquote banner at the top of the document (after the title), pointing to the authoritative source.

#### Scenario: HEALTH-AUDIT displays errata banner
- **WHEN** a developer opens `docs/audits/HEALTH-AUDIT-2026-06-21.md`
- **THEN** the first content after the title is a banner pointing to `docs/audits/HEALTH-AUDIT-2026-06-21-ERRATA.md` listing the 8 factually corrected items

#### Scenario: PROJECT-COMPLETION-SUMMARY displays stale banner
- **WHEN** a developer opens `docs/PROJECT-COMPLETION-SUMMARY.md`
- **THEN** the first content after the title is a banner stating the document is outdated, pointing to `docs/audits/debt-audit-2026-07-02.md` as the current status reference

#### Scenario: Banner does not modify document body
- **WHEN** a banner is added
- **THEN** the original document body content (after the title and banner) remains byte-identical to the pre-banner version

### Requirement: Documentation links are verified
Every internal link from `docs/README.md` (or any index file in `docs/`) to other `docs/` files MUST resolve to an existing file. External links (e.g., to GitHub, NVIDIA docs) MAY be present but are not required to be verified by this change.

#### Scenario: Link check passes for docs/README.md
- **WHEN** `markdown-link-check docs/README.md` (or `scripts/check-docs-index.sh` equivalent) runs
- **THEN** no broken internal `docs/` links are reported

#### Scenario: New link added with broken target fails check
- **WHEN** a developer adds a link in `docs/README.md` pointing to a non-existent `docs/` file
- **THEN** the check script reports the broken link, blocking the change from being merged

### Requirement: Skill list mirrors the canonical skills directory
`docs/skills/README.md` MUST list the same set of skills present in `.opencode/skills/` (excluding skills in `.opencode/skills.disable/`), and any skill moved to `.opencode/skills.disable/` MUST be marked as `disabled` in the docs list.

#### Scenario: three-mode-testing marked as disabled
- **WHEN** a developer opens `docs/skills/README.md`
- **THEN** the `three-mode-testing` entry is marked with a `[disabled]` indicator (commit `14c8eeb` reference)
- **AND** the entry remains visible for historical reference, not deleted

#### Scenario: New skill in .opencode/skills/ reflected in docs
- **WHEN** a new directory is created under `.opencode/skills/`
- **THEN** `docs/skills/README.md` is updated to include the new skill entry in the same change
